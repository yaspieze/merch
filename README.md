# Yaspieze store

The merch shop for Yaspieze. Static, no build step at publish time, no
back end: what is in this repo is what gets served.

Live at **store.fngl.ir**.

## What is here

Twenty pages, generated by one script from one product list.

| Page | What it is |
| --- | --- |
| `/` | The painted seasonal scene, collection tiles, a featured rail, the season's pick |
| `/shop/` | Everything, with live search, category and price filters, and sorting |
| `/collection/{apparel,accessories,homeware}/` | One page per collection |
| `/product/{id}/` | A page per product: gallery, colour and size pickers, details, related |
| `/sizes/` | How to measure, and real garment measurements |
| `/help/` | How ordering works, postage, care |
| `/about/` | Who is behind it |
| `/faq/` | Ten questions people ask before ordering |
| `/terms/`, `/privacy/`, `/returns/` | The pages a shop is expected to have |

## Building

From the workspace root:

```sh
python3 dev/store/build_store.py
```

That writes `Yaspieze Merch/`, ready to publish. It:

- reads `dev/store/store.css` and `dev/store/store.js`, strips their comments,
  and inlines both into every page;
- computes a `Content-Security-Policy` per page from the SHA-256 hashes of
  **that page's own** inline scripts, so the policy can never drift from the
  code;
- copies the product shots and the four painted scenes into `assets/img/`;
- writes `CNAME`, `robots.txt`, `sitemap.xml`, `_headers` and `.nojekyll`.

`dev/store/build_store.py` → `PRODUCTS` is the single source of truth. Add a
product there and every page, the sitemap and the search index pick it up.
`dev/store/store.js` → `CATALOGUE` is a second copy used by the basket, the
search and the quick view; if you add a product, update both.

## Things worth knowing before you edit

**The stylesheet is inlined into every page.** A relative `url()` inside it
would resolve against whichever page you are on, not against the stylesheet.
Collection tiles use a real `<img>` for exactly this reason.

**Every page carries a depth prefix.** The root is `""`, one level down is
`"../"`, two is `"../../"`. Links and asset paths are built with it rather
than hard-coded, and `window.YSP_PREFIX` does the same job in the script.

**The script is minified by stripping comments only.** Do not "improve" this
by collapsing whitespace: `/[&<>"']/` is a regex, not a string, and a
whitespace squeezer that tracks quotes will swallow the rest of the file and
ship a broken site. `verify()` parses the result before anything is written.

**Nothing takes a card payment.** The basket builds an order note the buyer
copies and sends by Discord or email. Stock is confirmed by hand, which is
why there is no checkout.

## Publishing

The repo is published straight from `main` by GitHub Pages. Two things need
setting up once, and only you can do them:

1. **GitHub** → the repo → Settings → Pages → Source: `main`, folder `/`.
2. **DNS** → a `CNAME` record: `store.fngl.ir` → `yaspieze.github.io`.

`CNAME` is already in the repo, so GitHub will accept the custom domain once
the DNS record points at it.

### Syncing this folder to the repo

The sync is an exact mirror: it copies everything in `Yaspieze Merch/` and
**deletes anything in the repo that is not in the built output**. That is
normally what you want, but it will eat repository-only files such as this
README. The delete step skips `README.md` for that reason.
